# GPHONE · v0.4.2 测试版

沿用 Roche 已配置的生图 API、模型及原生图片提示词，支持线上图片消息、线下生图和群聊人物照片。无需另填密钥，不需要电脑连接服务。安装直链：https://raw.githubusercontent.com/nellie01/GPHONE/main/manifest.json

## 使用

打开「GPHONE」→「人物参考库」→ 新建人物。可从 Roche 角色带入姓名，也可手动填写用户或其他人物。

每个人物独立保存：姓名、别名、外貌描述、脸部图、身材图、纹身图和一个自定义图位。自定义用途可填写“发型”“服饰”等。图片格都可以留空；没有图片时需要外貌描述。开启“按姓名自动引用此人物”并保存。

线上、线下及群聊生成的图片提示词中出现准确姓名或别名时，引用对应人物。合照可引用多个人。插件向角色注入格式说明，要求图片提示词只写实际出镜的人名，不写未出镜的发送者/摄影者姓名。插件本身匹配文字，无法可靠理解否定、引用和所有复杂语境；同名人物或别名冲突会被拒绝，避免猜测。

每张参考图都标注所属人物与用途。已上传的图作为对应部位参考；缺图的部位由生图模型依据人物外貌描述补足。优先级是发送给模型的要求，不保证每次成图严格一致。不会把别人纹身图上的脸当作本人脸部。照片提示词里未出现的人物不会从人物库自动附加。

原有按会话绑定的男女主设置保留。人物库姓名匹配优先；未匹配人物库时，可按会话的 male/female/both/none 标记区分男主自拍、女主照片、合照及无人风景。没有标记的旧会话提示词仍附上原来整组参考图，由模型按场景决定实际出镜者。

“角色保存的女主照片”指剧情中生成的图片，不是读取真实手机相册。

## 安装

将 JS 与 manifest.json 上传到同一静态托管目录，再从 Roche 导入 manifest 的 HTTPS 地址。支持 JS 直链的入口也可导入 JS 地址。本地 ZIP 不是可直接粘贴的安装网址。

## 保存与兼容

- 参考图存储在当前 Roche 站点、当前浏览器的独立 IndexedDB，清除站点数据会删除，不自动跨设备同步。原来单张人物图作为脸部图读取。
- 图片上传转为最长边 1400 像素 JPEG。仅在匹配的生图请求中发送至原有 API 服务。插件不保存密钥。
- 当前适配已核对的 `/assets/ai-core-C8ElbRIq.js` 构建；只读原生任务和会话状态，不改宿主数据库。Roche 升级可能需要更新适配。
- 支持直接的 OpenAI 兼容 `/images/generations` 和 `/images/edits`。有参考图时使用同一服务的 multipart `image[]` 编辑请求；仅文字描述时沿用文字生成。
- 代理 JSON 包装、其他协议及 NovelAI 暂不支持。服务商必须支持多图编辑，人数多时可能超过接口图片数量限制。
- 同一任务复用请求结果，避免原生回退重复付费。失败不会悄悄改成不带参考图生成。
- 关闭人物的自动引用开关，以及对应会话的旧参考图开关，可以停止引用。卸载后刷新网页可移除当前页面适配器。

## 验证

本地浏览器模拟测试通过：旧图迁移、2/8/7 张图片顺序、空格跳过、同任务防重复、失败拦截、会话隔离、线上男/女主体区分、群聊多人物、别名匹配、英文名字边界、纯外貌文字补足、人物编辑持久化。未调用用户付费 API，尚待手机真实出图验证。
