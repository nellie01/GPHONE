# GPHONE · v0.6.3 测试版

沿用 Roche 已配置的生图 API、模型及原生图片提示词，支持线上图片消息、线下生图和群聊人物照片。无需另填密钥，不需要电脑连接服务。安装直链：https://raw.githubusercontent.com/nellie01/GPHONE/main/manifest.json

## 使用

打开「GPHONE」→「人物参考库」→ 新建人物。可从 Roche 角色带入姓名，也可手动填写用户或其他人物。

每个人物独立保存：姓名、别名、外貌描述、造型与比例补充，以及脸部、眼部、发型/发色、身材、纹身、面罩、穿着和自定义共 8 个参考位。自定义用途保留，可填写其他细节。图片格都可以留空；缺图部位使用已有外貌资料。开启“按姓名自动引用此人物”并保存。

线上、线下及群聊生成的图片提示词中出现准确姓名或别名时，引用对应人物。合照可引用多个人。插件向角色注入格式说明，要求图片提示词只写实际出镜的人名，不写未出镜的发送者/摄影者姓名。插件本身匹配文字，无法可靠理解否定、引用和所有复杂语境；同名人物或别名冲突会被拒绝，避免猜测。

每张参考图都标注所属人物与用途。已上传的图作为对应部位参考；缺图的部位由生图模型依据人物外貌描述补足。优先级是发送给模型的要求，不保证每次成图严格一致。不会把别人纹身图上的脸当作本人脸部。照片提示词里未出现的人物不会从人物库自动附加。

原有按会话绑定的男女主设置保留。人物库姓名匹配优先；未匹配人物库时，可按会话的 male/female/both/none 标记区分男主自拍、女主照片、合照及无人风景。没有标记的旧会话提示词仍附上原来整组参考图，由模型按场景决定实际出镜者。

“角色保存的女主照片”指剧情中生成的图片，不是读取真实手机相册。

## 安装

将 JS 与 manifest.json 上传到同一静态托管目录，再从 Roche 导入 manifest 的 HTTPS 地址。支持 JS 直链的入口也可导入 JS 地址。本地 ZIP 不是可直接粘贴的安装网址。

## 保存与兼容

- 参考图存储在当前 Roche 站点、当前浏览器的独立 IndexedDB，清除站点数据会删除，不自动跨设备同步。原来单张人物图作为脸部图读取。
- 图片上传转为最长边 1400 像素 JPEG。仅在匹配的生图请求中发送至原有 API 服务。插件不保存密钥。
- 当前适配已核对的 `/assets/ai-core-C8ElbRIq.js` 构建；只读原生任务和会话状态，不改宿主数据库。Roche 升级可能需要更新适配。
- 支持直接的 OpenAI 兼容 `/images/generations` 和 `/images/edits`。有参考图时使用同一服务的 multipart `image[]` 编辑请求；仅文字描述时沿用文字生成。
- 代理 JSON 包装、其他协议及 NovelAI 暂不支持。服务商必须支持多图编辑，人数多时可能超过接口图片数量限制。
- 同一任务复用请求结果，避免原生回退重复付费。失败不会悄悄改成不带参考图生成。
- 关闭人物的自动引用开关，以及对应会话的旧参考图开关，可以停止引用。卸载后刷新网页可移除当前页面适配器。

## v0.5.0：user 与生成记录

人物库自动读取宿主的 user 身份列表，和角色联系人独立保存、标注“user”。每个 user 同样可以上传四张参考图、填写别名与外貌描述。刷新不会覆盖已填写资料；自动引用仍需开启。

打开 GPHONE → 生成记录，可查看每次请求的时间、来源、模型、匹配人物、参考图用途、选择与实际提交数量、是否附上外貌描述、HTTP 状态及失败原因。记录最多保留 200 条，保存在当前浏览器，清除站点数据会删除；不会发送到 GitHub，也不会补录升级前的请求。

接口返回图片后先标为“等待宿主显示”，观察到宿主接收图片后才标“生成成功”。页面关闭、刷新或无法确认时保留“结果未确认”，不自动重试。网络错误只能说明请求失败，不能单凭它确认服务端是否已生成或计费。记录中的数量表示请求携带的图片，并不保证模型一定遵循每一张参考图。

失败原因保留接口返回的错误说明（截断后显示），密钥、Authorization 和图片原始数据会被隐藏。只有可观察到的图片接口请求及本插件的提交前校验能记录；其他插件、未接入的协议、宿主在请求前报错等情况不保证有记录。图片接口配置和协议兼容限制沿用前文。


## v0.5.1：双人参考图补全

修复“只匹配到 user 姓名时，另一方的会话参考图被忽略”。明确双人画面会优先按提示词识别双方，并在私聊中用该会话的联系人与 user 身份补全缺失方；已开启的旧会话双人图片也可补足。群聊不会猜测缺失人物，必须在画面提示词中写出每位出镜者的姓名。未开启的人物、缺少资料或身份无法补全时，会在发请求前报错，不只用一方的图生成合照。

两人的脸部图优先排列，并分别标明所属人物。接口最终对参考图的遵循程度仍由模型决定。记录会列出实际发送的双方、各自张数及补全依据；画面摘要取原始场景，不再被宿主的单人锁脸前缀挤满。旧历史摘要不能补录，需要更新后重新生成一张检查。


## v0.5.2：多人参考板与自然画面引导

多人图默认在本地把双方（或多方）的原始参考素材合成一张分区清楚的参考板：每人一栏，脸部图最大，身材/发型/纹身等细节在各自区域标注。一次图片接口请求只上传这张板，不额外调用生图模型。这样可以减少部分中转接口仅处理第一张图片时，其他人的素材被漏掉的情况；不保证任何中转或模型都能严格还原每个人的脸。

人物库中的“多人图参考方式”可切回“分开发送原图”。单人场景继续按原来的方式发送该人的参考图。

内置自然画面引导词会结合本次场景及实际入镜人物拼接：以各人的脸部参考保留身份，其他参考仅引导对应部位；动作、表情、服装、镜头和光线跟随剧情，避免照搬参考照片的固定姿势、僵硬表情或背景。若剧情明确要求摄影风格，会补充自然皮肤纹理及真实光线要求；不会把明确指定的动漫/插画风格强改成照片。

生成记录区分原始素材数量与实际提交的参考板数量，并保留小尺寸预览，展开“查看本次提交的参考板”即可核对。预览保存在当前浏览器，不会上传 GitHub；日志数量不证明接口或模型已经遵循了每个参考特征。“生成成功”只表示宿主已接收图片，人物相似度尚未自动核验。

## v0.5.3：五官保留，朝向与视线跟随剧情

脸部参考只约束人物的五官和辨识特征，头部角度、眼珠方向、眼睑开合、表情及相机视角由本次剧情决定。参考板的标题、脸部标注和请求中的说明都采用这项规则，继续保留各人的身份分区及原始参考素材。

插件会引导角色在图片提示词里分别交代每位出镜者的动作、头部朝向、具体注视对象、自然表情和相机视角。例如剧情是女主看手中物、男主看她时，两人的视线分别对应物品与女主，不强制两人都看镜头；表情随情绪变化，避免目光放空。剧情明确要求看镜头、共同看某物、正面照或复现参考姿势时仍遵循，不随机改变方向。

单人图、多人参考板、分开发送原图及外貌文字补足都使用上述引导，不需要重新上传参考图。已验证实际发送的提示词、图片归属和构图指令保留；本地测试没有调用付费生图接口，最终角度、视线及相似度仍需新成图确认。

## v0.5.4：避免文字与图片重复添加外貌特征

人设、画面提示词和对应参考图里的同一颗痣、疤痕或纹身，应合并为同一处特征，不因重复描述而额外添加。对应图片已清楚显示的特征以该图的数量和人体位置为准，文字补充缺失信息；没有对应图片时按人物自己的外貌文字补足。真实设定中的多颗痣仍保留，不强制每个人只有一颗，也不删除原有雀斑。

朝向改变或局部被遮挡时，不将隐藏的痣挪到另一边或复制到可见皮肤。该说明同时加入聊天图片提示词引导与最终生图请求；不改写已保存的人设，不自动识别或修改参考照片，也不额外调用付费模型。请求检查通过不能保证模型每次准确还原，需要用更新后生成的新图确认。

## v0.5.5：第一人称与实际可见部位

修复第一人称“只露一只男性的手拿杯子”却附上双方人脸、要求双方露脸的冲突。对这类未写人物姓名或人像要求的旧提示词，保守识别手部视角，只按当前会话已有绑定引用相关的身体/纹身/服饰参考，不传脸部、发型和未出镜者的照片。无法确定手属于谁时保留场景文字，不自动塞入双方人脸。

角色生成的新图片提示词会带上拍摄方式、持机人、实际可见人物与部位的出镜说明。第一人称看对方、自己只露手时，各自只引用需要的部位；外部合照保留双方脸部，自拍和镜中场景可正常展示持机人。多人参考板只提供身份和部位资料，不再要求板上的每个人都露脸。画外摄影者不会因为拍摄行为就自动多出一只手，也不限制本来明确要求的多人场景。

没有可用于当前部位的参考图时，不发送无关的人脸照，按场景及已匹配的人物文字资料生成。出镜说明格式错误或同一人物通过别名重复列入时，在发送前拦截。记录保留实际提交的素材、出镜判断与筛选原因。

本地浏览器测试覆盖截图中的原始提示词、第一人称局部与对方人脸、画外摄影者、外部双人照、自拍、镜中、三人图、无人物场景、无可用部位参考及错误格式；未调用付费生图接口。提示词和参考筛选可以减少输入冲突，不能保证模型每次都不生成多余肢体。

## v0.5.6：每个人物独立保存造型要求

人物库和原有会话男女主设置增加“造型要求”栏，填写发型、发色、面罩覆盖范围或服饰。五官、辨识特征和年龄继续参考本人；明确保存的造型要求优先于参考照片附带的头套、旧发型及自动生成的画面造型，不将面罩或发型当作不可更改的五官。

可点“填入半脸面罩＋蓬松短发”，得到一个可编辑的示例：浅棕偏金、顶部蓬松有层次的短发，额前少量自然碎发；黑色骷髅面罩遮鼻口下巴，可自然衔接颈部布料，眉眼、额头、耳朵与头发露出。示例填入后先检查，再点“保存人物”或“保存设置”；不会自动套给所有人，不修改已有参考图或外貌描述，清空造型要求并保存即可停止使用。

请求只附上当前匹配人物各自的造型要求，生成记录会注明应用了谁的造型。第一人称只露手时仍受可见部位约束，不为展示发型或面罩而添加画外的人脸。多人参考、自然眼神、痣等特征合并规则继续使用。

造型文字不能还原被参考头套遮住的未知五官；如果希望更接近某张新照片的眉眼和发型，应将合适的照片上传为该人物脸部参考。插件发布文件不包含用户提供的照片。已验证造型保存与隔离、示例草稿、清空、旧设置兼容、请求优先级和第一人称约束；未调用付费生图接口，最终造型与相似度需新图确认。

## v0.6.0：8 个参考位、原有人设身形与巴拉克拉瓦

每人由 4 个扩展为 8 个参考位，原脸部、身材、纹身和自定义图片保留，不要求重传。新增眼部、发型/发色、面罩与穿着；原有会话男女主设置也可分别使用 8 个图位。连续上传的图片排队保存，避免后一次上传覆盖尚未完成的图片。

眼部位建议放眉眼近景，保留眼型、眼距、眉形和虹膜颜色，冲突的画面眼睛颜色词不能覆盖它；注视对象、眼珠方向和表情仍随剧情。面罩只提供布料结构和图案，穿着只提供衣服，不把这些图里模特的眼睛、脸或体型借给角色。身材位建议放全身或头肩、四肢比例清楚的图片。

人物库增加独立的面罩佩戴方式：按剧情、巴拉克拉瓦只遮下半脸（露发）、全头覆盖或不佩戴。下半脸模式是头套上部向后褪下或卷下，鼻口、下巴至颈部仍为连续弹力布料和自然褶皱，保留骷髅图案，不转成耳挂口罩、医用口罩、硬壳呼吸器或彩绘。保存的模式优先于画面中冲突的 no mask 或全头覆盖描述，同时保留本人眼部特征。使用过 v0.5.6 原始造型示例、且没有手工修改的，在读取时升级为此说明；自定义造型不覆盖，原始资料在下次保存前不改写。

身高与体型直接沿用原有人物描述，无需重复填数字。生成时只读已绑定的角色和 user 外貌段落，并和插件内手写外貌合用；同项以手写补充优先。明确且无歧义的身高会进入相对身高数据，支持常见厘米、米和中文“身高一米七五”等写法；多个不同身高无法确定归属时不猜数字，保留原描述。生成记录注明读取了谁的人设、沿用了哪些身高，不保存整段原生人设到日志或 GitHub。

“身形与比例补充”可留空，已有设定不必抄写；也可选用成年娇小体型示例，再检查保存。参考板上的照片为可读性独立缩放，不表示物理头部大小或实际身高。画面应考虑坐姿、坐在对方腿上、前后距离与裁剪，保持协调的成年头肩和头身比例，不把较矮的人画成大头儿童，也不机械按站立身高对齐坐姿头顶。

参考板随素材数量增加高度，眼部单独放大，其他细节最多分三列多行显示，避免新图位挤成一排小图。只露手或局部时继续筛掉不需要的脸部、眼部和发型，造型要求不增加画外人物。

本地测试覆盖旧图兼容、实际上传 8 图、连续保存、原生人设身高读取和独立归属、单位解析、歧义数字跳过、手写补充优先、眼部单独参考、面罩关闭筛选及原有生成/滚动/记录功能。未调用付费生图接口，最终身形、眼睛与面罩效果仍需新图验证。

## v0.6.1：相机描述一致、保留出镜人物与面罩贴合

修复“第三视角拍摄、Simon”后面仍接整段 first-person perspective 的矛盾输入：按正文开头明确指定的拍摄方式统一相机描述，保留书、猫、椅子等场景和动作，将单人场景里的手与腿归属该人物。正文只点名 Simon 时不会仅因当前会话保存双方参考图就再加入 Nellie；旧会话里的简称仍可匹配原有资料。

聊天提示词引导不再默认偏向第一人称，按剧情生成自拍、外部人物照、合照、镜中或真正的第一人称画面。出镜辅助数据支持 scene，让普通照片按剧情决定裁剪；正文明确要求出镜的人物不会仅因辅助数据漏写而被删去。真实第一人称与明确只露手等局部要求仍保留，画外摄影者不自动加入画面，不固定限制人物数量。

面罩尺寸按当前人物的鼻梁、脸颊、下颌和下巴适配，不能照搬参考照片的脸宽或为了适应布料而改变人物脸型。弹力布料保持自然接触、细小张力褶皱和可信厚度；颈部贴合，只留少量细褶，褪下的上部布料平整收在后颈，避免变成宽围脖、厚布圈或下巴下悬空的大布袋。明确要求宽松穿戴时仍尊重该人物的要求。

骷髅图案的覆盖范围与布料大小是两件事。若参考图的印花跨过脸颊和下颌，不能把整个骷髅缩成集中在鼻口的小标志；按鼻部、两颊、嘴部和下巴的对应位置适配，并随面部曲面、透视、布纹、细褶与光照变形。扩大印花覆盖不等于放大整块面罩，也不要求把印花铺到整个颈部。保留参考设计，不统一规定所有图案的大小，不给纯色面罩凭空添加骷髅。

此引导仅在相应人物实际佩戴面罩、且相关部位可见时适用，不覆盖“不佩戴”设置，不改变露发模式或眼部参考，不为展示面罩添加画外人脸。生成记录会标明哪些人物附了面罩贴合引导，也保留统一后的场景提示词和拍摄视角。已检查截图中的原始提示词、旧会话简称、真正的第一人称、自拍、镜中、双人及多人画面、画外摄影者、面罩关闭和局部手部场景；没有调用付费生图接口，实际出镜、贴合与印花效果仍需新成图确认。

## v0.6.2：可见眉眼与面罩印花分工

修正印花牙齿对齐真人嘴部的引导：骷髅是布料上的整体图案，保留鼻部图形、两颊、牙列和下巴区域的相对比例，随当前面部曲面、布料与透视变形。不能缩到隐藏嘴巴的宽度，不能把印花牙齿对应真人牙齿，也不能按印花轮廓改变人物下颌。先确定人物体积，再贴合布料，再呈现布料上的图案；黑色骷髅鼻孔是印花，不是人体鼻子或穿透布料的洞。

戴面罩的脸部参考只提供可见的解剖特征；眼部图优先提供眼型、眼距、眉骨和虹膜特征，视线与表情仍随剧情。布料边缘、眼洞缝线、印花眼窝不当作本人五官，图案不覆盖人物身份。被完全遮住的嘴唇、下颌等不能从这一张图准确得知，有本人无遮挡参考或文字外貌时用于补足，不把“上传成功”当作已验证完整脸型相同。

多人参考板将独立的面罩参考放大为单独图位，保留原有脸部、眼部和其他人物分区。面罩位适合上传布料及图案清楚的近景，脸部与眼部位放本人的对应资料；自定义用途明确为面罩的旧图片也支持独立放大。不自动裁剪或重画用户照片，不为展示参考图增加画外人物，不重新上传私人图片到 GitHub。关闭面罩或只露手时继续筛选相关资料。

新生成记录标注插件版本，使用参考板时注明哪些人的面罩参考独立放大。旧记录不补写版本；更新只影响之后的新请求。已验证提示词的局部归属、图案与真实五官分工、放大参考的实际像素及人物隔离、面罩关闭和视角规则。没有调用付费生图接口，也没有自动核验成图的相似度，最终贴合与眉眼效果需要新图确认。

## v0.6.3：面罩前缘与眉眼身份

前缘按对应参考图真实的缝边、印花间距和结构处理。参考只有贴脸窄缝边时，不凭空添加宽黑带、双层平行边、眼下翻卷布圈或向耳侧悬空伸出的布条。露发模式将头套上部退至后颈，前侧保留原眼洞下缘的贴脸边，不把褪下的头套卷成眼下黑边。保留本来存在的黑色侧面、颈部布料、印花和真实宽包边，不统一抹掉黑色或强制所有款式改成窄边。

更换发型、露出额头只改变头发和头套覆盖，不重新设计眉眼身份。眼型、眼睑结构、眼角、眼距、虹膜和可见眉骨/眉形优先用本人眼部图，没有时用本人脸部图，不借用发型照片里的模特五官。头部朝向、注视目标与自然表情仍随剧情；本人的脸部/眼部图若清楚显示眼周妆容，可保留对应妆容，不能把妆容或布料边缘当成另一层面罩。被头套完全遮住的眉毛或其他五官仍不能从图片精确得知。

多人参考板增大独立眼部图位。没有独立面罩图时，若同一个人的脸部参考明确戴着面罩，也可用于该面罩的布料、边缘和印花；印花仍不当作真实五官，不借用其他人的面罩照片判断本人眉眼。生成记录注明每个人的眉眼实际来自眼部图、脸部图或外貌文字。
